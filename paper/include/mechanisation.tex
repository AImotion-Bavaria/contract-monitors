The definitions and theorems of Sects.~\ref{sec:contracts}--\ref{sec:compositional} are formalised and proved in Lean~4~\cite{deMouraUllrich2021}. The development uses the core library only, comprises about 1,250 lines, and contains no unproved statement.

\paragraph{Structure.}
Table~\ref{tab:lean} relates the modules of the development to the paper. Contracts are formalised as pairs of predicates over infinite traces, monitorable contracts as pairs of decidable predicates over finite prefixes. Channels and syntactic interfaces are layered on top: a predicate \emph{observes} a set of channels if it is invariant under hiding all other channels, and a monitor is \emph{local} to a set of channels if it is fed with these channels only.

\paragraph{From Proof to Execution.}
Lean is a programming language as well as a proof assistant. The synthesis function of Sect.~\ref{sec:synthesis} is an ordinary Lean function; the monitor it returns is the object about which Theorem~\ref{thm:synthesis} is proved and, at the same time, the code that is compiled and executed. Hence, there is no separate code generator whose output would have to be trusted or validated. The development contains executable checks that evaluate synthesised monitors for instances of all patterns on sample prefixes.

\paragraph{Trusted Base.}
The proofs are checked by the Lean kernel and rely on the standard axioms of Lean only (propositional extensionality, quotient soundness, choice). What remains to be trusted is (i)~that the formal definitions capture the intended notions, in particular the semantics of Def.~\ref{def:semantics}, (ii)~the Lean compiler and runtime, and (iii)~the adapter that samples the observed channels in each interval and passes the valuation to the monitor. The adapter lies outside the formal model; we return to it in Sect.~\ref{sec:discussion}.
